# 隐私设置与验收

## DNS 和 WebRTC 的实际边界

DoH 加密只能防止链路明文观察，不能自动隐藏你的源 IP。要让 DNS 解析服务也只看到代理 IP，必须核验 Loon 自身 DoH 请求是否经过同一节点。普通 DOMAIN/IP 分流规则不应被当作 Loon 内部解析器已走代理的证据。本包没有虚构“强制 DNS 代理”的未确认参数。

hijack-dns = *:53 针对进入 TUN 的 UDP DNS，不拦截一切 TCP DNS、DoT、应用内 DoH 或隧道外请求。代理节点域名解析属于另外一条路径；若可用固定 IP 作为节点地址，可以减少引导 DNS 依赖，但须保留节点所需的 SNI/Host 和证书校验。

disable-stun 减少 STUN UDP 暴露，不是完整禁用 WebRTC。udp-fallback-mode = REJECT 防止不支持 UDP 时回落直连。这些设置影响整机，可能影响实时音视频。没有默认全局禁止 UDP 443，避免影响基于 QUIC 的代理节点。

## Mac 与移动端

Mac：路径规则覆盖标准安装位置的主程序和 helper；名称规则作为补充。进程识别失败时只能依赖域名规则。进程规则不按父子关系继承，任意 node/python、本地 MCP、外部浏览器、Cowork 虚拟机流量不保证被覆盖。

iOS/iPadOS/tvOS：忽略进程规则，使用域名分流；已知 Claude 域名访问走指定策略，不等于全部 Claude App 请求都已覆盖。第三方登录、遥测、CDN、IP 直连可能遗漏。不要为补漏把所有 cloudflare.com/google.com 等共享域名无差别加入。

如果移动端要求使用 Claude 时所有未知目标也不能直连，应在使用期间切换 Loon 全局代理到同一个固定节点。这会影响其他 App，且仍须验收 DNS、绕过项和 Loon 停止后的行为。普通模块无法等价实现 iOS 每应用 VPN。

## 验收清单

1. 导入后无语法错误；插件策略明确绑定到目标节点或指定组；若使用组，该组仅有目标节点。
2. Mac 请求记录检查主进程与 Helper、登录、上传、下载、流式聊天、语音等实际用到的功能：确认最终策略与节点，而不只是命中规则名称。移动端分别检查域名请求。
3. 如发现 Claude 请求命中本地旧规则或 DIRECT，先处理冲突，不宣布通过。
4. DNS 检查：在物理网卡抓包核验是否出现外发 UDP/TCP 53、853，以及直接到 DoH 服务的 443 连接。仅看到没有 53 端口不能证明没有 DNS 泄漏；应用自带 DoH 也需要观察。节点自身的连接要与目标请求区分。
5. 保持 Loon 运行，让指定节点暂时不可达，确认 Claude 请求失败，未切到 DIRECT 或其他节点。不要通过关闭整个 Loon 来模拟节点失败。
6. 再分别验证 Wi-Fi/蜂窝切换、休眠唤醒、重启；Loon 退出后不受本模块保护，这是已知限制，不作为可保证的断网开关。
7. 浏览器 DNS/WebRTC 检测只能反映该浏览器，不代替 Claude 进程验证；时区不在本模块保护范围。

## 回滚与扩展

关闭插件，并恢复备份中的主配置与 DNS 回落设置。只关闭插件不会撤销主配置修改。

要增加其他 App，复制一份模块，改名称、Mac 进程名称/路径及独立域名列表，再为该插件绑定目标策略。不要用通用 *Helper*、node、python 规则，避免将其他程序一并纳入。
